# Stripe Connect signup flow

`POST /api/register` only emails an OTP. `POST /api/verify-otp` takes the normal registration fields; `return_url` and `refresh_url` are optional, but must be provided together if the mobile app has its own HTTPS callbacks. Otherwise the API uses its own `/stripe/onboarding/return` and `/stripe/onboarding/refresh` routes under `STRIPE_ONBOARDING_BASE_URL` (defaults to `APP_URL`). After validating the OTP, the API creates the local user and a Stripe Express connected account through Accounts v2 under the platform's `STRIPE_SECRET`, then saves the returned ID in `users.stripe_account_id`. The verification response includes the ID in `data.user.stripe_account_id`, a Sanctum token in `data.token`, and a single-use hosted Account Link in `data.onboarding_url` with `data.onboarding_link_expires_at`. The account requests merchant `card_payments` and recipient `stripe_balance.stripe_transfers`; no payment is created at registration.

The connected account cannot receive payments just because it was created. The signed-in user must complete Stripe-hosted onboarding:

1. Open the signup response's `data.onboarding_url` in a browser, not an embedded mobile WebView. If it is null, expired, or already used, call authenticated `POST /api/stripe/onboarding-link` to get a fresh `data.url`. The API keeps the completed signup if initial link creation fails.
2. The default backend refresh route shows a page asking the user to return to the app and request a new link. It does not create another link in an unauthenticated browser session. The mobile app should call the authenticated link endpoint again and open the new URL. If the app supplies its own `refresh_url`, its handler can perform that step directly.
3. The default backend return route asks the user to return to the app. When the app resumes, it should call `GET /api/stripe/account-status` with the bearer token. A return from Stripe does not prove onboarding is complete. Check `data.ready_for_payments` and `data.onboarding_required`; show another onboarding action while current or eventual requirements remain. Stripe can also be reviewing an account that has no outstanding onboarding fields. The status endpoint uses the v1-compatible Account representation exposed for the Accounts v2 connected account.

Both callback URLs must be HTTP(S) URLs. Stripe test mode accepts HTTP for local testing; live mode requires HTTPS. Set `STRIPE_ONBOARDING_BASE_URL` to the public API base URL (including a deployment path such as `/bezzie`); `http://localhost` will not work from a mobile device. The local AMPPS value is `http://localhost/bezzie`. The API hosts the default callback pages. Never expose `STRIPE_SECRET` in the client app or put the bearer token in a callback URL. Do not store onboarding URLs in the database: they expire and are single-use. Store the connected account ID and query `GET /api/stripe/account-status` for current activation state.

## Provider payouts

New Express accounts use a manual payout schedule so providers can withdraw their available balance from the mobile wallet. Existing accounts are switched to manual scheduling when their first in-app payout is submitted.

The provider wallet reads `GET /api/freelancer/payouts`, which returns Stripe's available and pending connected-account balances, a masked default payout destination, and local payout history. `POST /api/freelancer/payouts` accepts an amount plus a client-generated idempotency key and creates a standard Stripe Payout on the connected account. The amount is checked against Stripe's available balance, not the application's lifetime earnings total. The minimum is configured in smallest currency units with `STRIPE_MINIMUM_PAYOUT_MINOR` (default `1000`, or AUD 10.00).

Providers manage or replace their bank account through a single-use Express Dashboard login URL returned by `POST /api/freelancer/payouts/dashboard-link`. Bank account numbers never pass through or persist in the mobile app or backend.

Configure the Connect webhook endpoint to send `payout.created`, `payout.updated`, `payout.paid`, `payout.failed`, and `payout.canceled` events to `/api/stripe/webhook`. The API also reconciles recent Stripe payouts whenever the wallet loads. Test-mode payouts change state but do not move real money. When `STRIPE_TEST_PLATFORM_PAYMENTS=true`, test job charges stay on the platform balance and therefore do not increase a provider connected-account balance.
